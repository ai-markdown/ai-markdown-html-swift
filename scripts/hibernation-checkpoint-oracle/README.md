# Raw-tokenizer hibernation checkpoints

The self-contained oracle bundle executes the fixed Web parse5 7.3.0 and @ai-markdown/hast-util-raw 9.1.3 from Web `e9ec1799fdc380d99ce0a6313023515895bbd7bf`. The producer passively observes actual tokenizer writes, state, consumed UTF-16/UTF-8 counts and pending character locations; it separately repeats every real operation without observers. It does not generate expected positions from a native result or a desired HAST endpoint.

Run `node scripts/hibernation-checkpoint-oracle/export.mjs --check` without a Web checkout to replay all 347 controls and check the bundled runtime, source manifest and full licenses. To intentionally refresh the frozen source, run the same producer with the exact fixed Web checkout path. The matrix includes every scalar prefix of comment, DOCTYPE and CDATA declarations, ASCII and Unicode/CRLF containers, consecutive raw writes, and generated-node interruption. There are 315 complete successful Web trees and 32 preserved real Web TypeErrors; exception controls are not claimed as native/Web tree parity. All 225 observed early checkpoints are in the actual declaration-open state (41).

parse5 `preprocessor.startsWith` sets `endOfChunkHit` when a requested lookup length is unavailable, including a mismatching short prefix. `_stateMarkupDeclarationOpen` first tries `--`, then the seven-character DOCTYPE and CDATA sequences. Unless the two-character comment sequence already matched, fewer than seven remaining UTF-16 characters trigger `_ensureHibernation`, which retreats the speculative current character. The native reader is positioned at that character's UTF-8 start before lookup. It records that actual checkpoint and drops the speculative remaining raw-node bytes while retaining declaration-open state for the next raw write. Generated elements preserve the actual tokenizer state; a generated text node separately resets tag-like states. Complete ordinary parsing without emission boundaries keeps its behavior.

The opt-in event `raw-hibernation-end` identifies the actual pending Char token when one exists (otherwise `token` is nil) and carries `rawEnd:checkpoint` in `note`, both original input UTF-8 offsets. Input normalization maps both offsets back from the tokenizer buffer. An Engine consumer must validate the event, token, raw-emission boundary and checkpoint before using it; the raw node's byte length is not a substitute for this evidence.
